# 控制流等价

每条格式：**模式 → 危险（通道）→ 行为保持的改写 → 反例**。
"通道"指验证系统对比的 observable channel：exit code / signals / stdout / stderr / filesystem。

## 1. 短路求值的副作用顺序就是行为

**模式**：`if (f() && g())`、`a || b`、条件表达式里的函数调用。

**危险（通道）**：把 `&&` 改成嵌套 if 是安全的当且仅当两分支求值次数不变；
反过来把嵌套 if 合并成 `&&` 时，若第二个条件有副作用（IO、修改全局、
指针推进），求值次数变了 → **stdout / 文件系统副作用漂移**。

**行为保持的改写**：
- `A && B` → 嵌套 if：允许（求值次数、顺序都不变，B 只在 A 为真时求值）；
- 嵌套 if → `A && B`：仅当 B 无副作用且求值次数相同时允许；
- 三元 `c ? a : b` 重排：两侧求值的条件互斥性必须保持。

**反例**：
```c
/* 坏：把 if (p && *p++ ) 合并/拆开 —— *p++ 的自增次数变了，
   后续所有指针偏移漂移 → stdout 漂移 */
```

## 2. 提前 return：控制流简化的合法形状

**模式**：深层 `if (err) {...} else {...}` 金字塔。

**行为保持的改写**：转成 guard clause（`if (err) return code;`）是安全的，
**前提**：
- 每个 return 的值与到达点完全一致；
- else 分支原本执行的所有语句在早退路径上确实不执行（特别是输出语句）；
- 早退不跳过任何原本会执行的副作用（原本的金字塔里没有"最后统一释放"
  之类的路径，若有，见 error-paths.md 的清理链条目）。

**危险（通道）**：漏算 else 分支里的副作用 → **stdout / 文件系统漂移**。

## 3. 循环改写：边界变量与 continue/break 是契约

**模式**：for ↔ while 互换、循环展开、把 `continue` 重构成 if 包裹。

**行为保持的改写**：
- for → while：初始化/条件/自增三段的求值次数必须逐一对应（for 的 continue
  仍走自增，while 的 continue 不走——直接搬会死循环或跳过自增）；
- 展开（unroll）：迭代次数不整除展开因子时的尾差必须与原语义一致；
- `continue` → `if (!cond) {...}`：continue 跳过的必须是"循环体剩余部分"，
  若循环体后面还有别的语句，包裹范围错误 → **stdout 漂移**。

**反例**：
```c
/* 坏：for (i=0;i<n;i++){ if(x) continue; f(); g(); }
   → if (!x) { f(); g(); }  正确；但漏掉 g() 就把副作用丢了 */
```

## 4. goto 清理链：结构化改写的高危区

**模式**：`goto cleanup;`、多级 `if (fail) goto out;`、`out:` 后统一释放。

**危险（通道）**：释放顺序错 → 错误码/退出行为漂移；漏一次释放 → 资源句柄
耗尽路径不同 → **exit code / stderr 漂移**；改成嵌套后某条路径多输出一行 →
**stdout 漂移**。

**行为保持的改写**：
- 保持清理的**逆序**（后申请先释放）与**全部路径**（每条失败分支都过同一清理集）；
- `goto out` 里若有 `return` 前的最后输出，搬移时输出语句一字不动；
- 证明不了每条路径的清理集完全一致 → 不改，保持 goto。

## 5. 求值次数与序列点：`i++ + i` 类陷阱

**模式**：`a[i++] = i;`、`f() + g()`（f/g 有副作用）、逗号表达式、
把 `x = x + 1` 与 `x++` 混用重排。

**危险（通道）**：同一序列点内对同一对象修改两次或读写混排 = UB →
**stdout / exit code 漂移**；副作用跨序列点重排 → 值漂移。

**行为保持的改写**：
- 拆语句是安全的（`a[i++] = i;` → 先存 i 再自增，但必须先证明原代码不是
  依赖 UB 的——原代码若已是 UB，保持原样不要动）；
- 不把两个有副作用的调用合并进一个表达式，也不拆开本来就并排求值的
  `f() + g()`（求值顺序 unspecified，但两侧次数不变才是关键）。

## 6. switch ↔ if-else 链：fallthrough 与 default 的位置

**模式**：switch 的 case 故意 fallthrough（无 break）、default 不在末尾。

**危险（通道）**：改写成 if-else 时丢掉一个 fallthrough 分支的语句块 →
**stdout / exit code 漂移**；default 位置改变不影响语义但重排 case 顺序会
（case 匹配互斥时安全，有 fallthrough 链时危险）。

**行为保持的改写**：
- 逐 case 对照：每个 case 的语句块、是否 fallthrough、是否读 `errno`（见
  error-paths.md），全部映射后再动；
- 有 fallthrough 链时保持 switch 形状最安全——只做语句级清理，不做结构转换。
