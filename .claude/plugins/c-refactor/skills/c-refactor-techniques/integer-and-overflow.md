# 整数与溢出

每条格式：**模式 → 危险（通道）→ 行为保持的改写 → 反例**。
"通道"指验证系统对比的 observable channel：exit code / signals / stdout / stderr / filesystem。

## 1. 有符号整数溢出是 UB，不是"回绕"

**模式**：`int total = a + b;`、`i++` 靠近 `INT_MAX`、`-x` 当 `x` 可能是
`INT_MIN`、移位超过位宽、有符号与无符号数混比。

**危险（通道）**：开启优化后编译器假定 UB 不发生，可能整段分支被删除或重排 →
**exit code / stdout 全部可能漂移**；UBSan 构建下直接产生 findings。

**行为保持的改写**：
- 边界检查写成"入口守卫"（提前 return 原错误码），再写算术；
- 需要回绕语义时显式用无符号类型计算，再显式转回；转换前后的位型用
  固定宽度类型（`int32_t`/`uint32_t`）钉死；
- 混比先统一宽度：`(int64_t)a < (int64_t)b`，不依赖隐式提升。

**反例**：
```c
/* 坏：把 a+b 挪进 if，编译器可能因 UB 假设直接删掉溢出分支 */
if (a > 0 && b > 0 && a + b < 0) return -1;   /* 旧代码 */
int s = a + b;                                /* 新代码把加法提出去 —— 两者不等价 */
if (s < 0) return -1;
```

## 2. 隐式转换与窄化：值不变 ≠ 行为不变

**模式**：`size_t` 与 `ssize_t`/`int` 混算、`long` 赋给 `int`、
枚举当 int 用后又比大小、`char` 参与算术（符号性依平台）。

**危险（通道）**：窄化丢位后比较结果翻转 → 错误分支走向变化 →
**stdout / exit code 漂移**；符号性变化让负数变巨正数 → 循环次数变化。

**行为保持的改写**：
- 改写前后保持每个中间量的类型与宽度不变——提取函数时**照抄声明**，
  不"顺手换成更安全的类型"；
- 必须跨宽度比较时用显式 cast 写清意图，且改写前后两侧都做同样的 cast；
- `char` 参与算术时先想清楚本平台它是 signed 还是 unsigned（改动前先看
  它已被怎么用，不要引入新假设）。

**反例**：
```c
/* 坏：len 是 size_t，旧代码 (int)len > 0；新代码直接 len > 0。
   len = (size_t)-1 时旧代码走 false 分支，新代码走 true 分支 —— stdout 漂移 */
```

## 3. 移位：位数与符号都有红线

**模式**：`x << n`（`n >= 位宽`、`x` 为负、`n` 为变量）、`1 << 31`（int 溢出 UB）。

**危险（通道）**：UB 给编译器自由 → 值不可预测 → **stdout 数值 / exit code 漂移**。

**行为保持的改写**：
- 常量移位改用固定宽度无符号类型：`(uint32_t)1u << 31`；
- 变量移位保持原有守卫不动（`if (n >= 0 && n < 32)` 这类守卫是行为的一部分，
  不是累赘——删掉它就是删掉已定义性）；
- 不把 `x << n` 重写成 `x * 2^n`：溢出时一个 UB 一个定义良好，值可能不同。

**反例**：
```c
/* 坏：把守卫移走或合并 —— n==32 时旧代码走 else，新代码变 UB */
if (n >= 0 && n < 32) v = x << n; else v = 0;   /* 旧 */
v = n < 32 ? x << n : 0;                        /* 新：x 为负时仍是 UB，旧代码也是 —— 保持原样，不要"顺手修" */
```

## 4. `INT_MIN` 取负与边界重排

**模式**：`-x`、`abs(x)` 当 `x` 可能是 `INT_MIN`；把 `a - b` 重排为 `-(b - a)`。

**危险（通道）**：取负溢出 UB → **stdout / exit code 漂移**。

**行为保持的改写**：
- 保持原式的形状与求值序；需要取负时先判 `x == INT_MIN`（或所在宽度的
  最小值）走原路径；
- 重排加减法前先证明每个中间结果在两种形状下都不溢出——证明不了就别重排。

## 5. 无符号下溢是已定义的，但你的改写可能改变它

**模式**：`size_t n; ... n - 1` 当 `n == 0`（回绕成 `SIZE_MAX`）、
循环 `for (size_t i = n - 1; ...)`。

**危险（通道）**：无符号回绕是**已定义行为**，值固定为 SIZE_MAX——但如果你
"好心"改成有符号或加了守卫，条件结果就变了 → **stdout / 循环副作用漂移**。

**行为保持的改写**：
- 原代码依赖回绕（如 `n == 0` 时循环体不执行）→ 保持形状原样，只做结构重组；
- 原代码有 `if (n > 0)` 守卫 → 守卫是行为的一部分，保留；
- 绝不借重构之机"修复"下溢：那是行为变更，不是重构。

## 6. 枚举与位标志：宽度与符号跟着实现走

**模式**：把枚举值存进位域/`int`/`unsigned`、`flags |= A | B` 重排、
组合枚举当 bitmask 用。

**危险（通道）**：枚举的实现定义宽度/符号改变存储解释 → 比较/打印结果漂移 →
**stdout / 文件内容漂移**。

**行为保持的改写**：
- 存储枚举的容器类型不改；`|`/`&`/`~` 组合的形状保持；
- 位操作重排（`a | b | c` → `a | (b | c)`）仅当全部操作数无符号且宽度不变时
  才是安全的——枚举底层类型是实现定义，别赌。
