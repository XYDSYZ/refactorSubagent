# 宏

每条格式：**模式 → 危险（通道）→ 行为保持的改写 → 反例**。
"通道"指验证系统对比的 observable channel：exit code / signals / stdout / stderr / filesystem。

## 1. 函数宏的参数是按出现次数复制的：副作用乘以出现次数

**模式**：`#define MAX(a,b) ((a) > (b) ? (a) : (b))` 配 `MAX(x++, y)`、
`MAX(f(), g())`（f/g 有 IO）。

**危险（通道）**：展开后自增执行两次、IO 执行两次 → **stdout / 状态漂移**。
这是宏最经典的坑：改写宏本身或改写调用点都可能改变求值次数。

**行为保持的改写**：
- 不把函数宏"升级"成内联函数来"修复"多次求值——原代码的调用点若已传入
  带副作用的参数，宏与函数的求值次数不同 = 行为变更（即使修复了 bug）；
- 宏体里每个参数的括号数量、`?:` 的结构保持原样；提取"等价"宏时逐 token 对照。

**反例**：
```c
/* 坏：#define MAX(a,b) ... 改成 static inline int max(int a,int b)
   调用点 MAX(x++, y)：旧代码 x 自增两次（MAX 若取 b 仍自增一次），
   新代码 x 只自增一次 —— stdout 里打印 x 的值就漂移了 */
```

## 2. 多语句宏必须保持 do{}while(0) 形状

**模式**：`#define SWAP(a,b) { int t=a; a=b; b=t; }` vs
`do { ... } while(0)`。

**危险（通道）**：裸花括号宏在 `if (c) SWAP(x,y); else ...` 处展开后
`else` 悬空 → **编译失败**（宿主验证前你该用 Bash 自编译抓到）；
行为上，若原代码是 do-while(0) 而你换成裸块，某些调用点上下文里
控制流直接改变。

**行为保持的改写**：
- 宏体的包裹形状原样保留：do-while(0) 就 do-while(0)，裸块就裸块；
- 不借机"规范化"宏体——形状是它与所有现存调用点的契约。

## 3. #if 分支：没被编译的分支不是可删的死代码

**模式**：`#ifdef DEBUG`、`#if SIZEOF_LONG > 4`、平台条件编译。

**危险（通道）**：删"当前平台不激活"的分支 = 改变其他平台/配置下的行为；
改条件表达式可能让**当前配置**激活了不同分支 → 立即 **stdout / exit code 漂移**。

**行为保持的改写**：
- 条件编译的分支与条件表达式原样保留（重构内部结构时把它们当作不可见边界）；
- 不合并 `#if` 与 `#else` 里的重复代码——它们在不同配置下各自是唯一路径；
- 判"死代码"只对运行时不可达成立，预处理条件分支不在其列。

## 4. token 粘贴与字符串化：展开结果就是行为

**模式**：`#define CONCAT(a,b) a##b`、`#define STR(x) #x`、
`#define STRV(x) STR(x)`（两层展开）。

**危险（通道）**：粘贴结果的标识符不同 → 链接不同符号 → **编译失败或
链接到不同实现** → 运行行为漂移；字符串化结果变了 → **stdout 漂移**。

**行为保持的改写**：
- `##` 与 `#` 的位置、层数（单层 vs 双层展开的差别）逐 token 保持；
- 不把宏改写成等价函数当宏用于拼接场景（函数没有 token 语义）。

## 5. 对象宏的"常量"有类型：展开点的表达式继承它

**模式**：`#define LIMIT 1024`、`#define LIMIT (1L << 10)`、
`#define NEG (-1)`——类型分别是 int、long、int。

**危险（通道）**：改写常量的写法改变了类型/宽度 → 比较与提升结果变 →
**stdout / exit code 漂移**（如 `LIMIT - 2` 在 LIMIT 为 int 时下溢行为与
long 时完全不同——不过两者都定义良好，值不同）。

**行为保持的改写**：
- 后缀（L/U/UL）、括号、负号形状逐字保持；
- `#define NEG (-1)` 的外层括号防的是 `NEG - 1` 展开成 `-1 - 1`（OK）vs
  `-1 - 1` 无括号时的意外结合——形状即契约，照抄。

## 6. 宏定义的位置与作用域：#undef 是行为的一部分

**模式**：文件中部 `#undef X` 后重定义、条件重定义（`#ifdef` 内两套 X）。

**危险（通道）**：重定义顺序或作用域变了，后半文件展开结果不同 →
编译失败或 **stdout 漂移**。

**行为保持的改写**：
- 宏的生命周期（定义点 → #undef 点）当成作用域边界，不把定义"提升"到
  文件头"统一管理"——那会改变中部代码展开所用的定义版本。
