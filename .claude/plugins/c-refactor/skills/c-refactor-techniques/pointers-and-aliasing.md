# 指针与别名

每条格式：**模式 → 危险（通道）→ 行为保持的改写 → 反例**。
"通道"指验证系统对比的 observable channel：exit code / signals / stdout / stderr / filesystem。

## 1. memcpy 重叠区是 UB，memmove 不是——语义靠边站，UB 优先

**模式**：`memcpy(d, s, n)` 当 `d`、`s` 可能指向同一数组的不同偏移
（自拼接、滑动窗口、`d == s`）。

**危险（通道）**：重叠拷贝是 UB，优化实现可能按任意方向拷贝 → 结果字节不确定 →
**stdout / 文件内容漂移**。原代码"碰巧没重叠"不等于改写后也不重叠——你改了
调用点的传播路径。

**行为保持的改写**：
- 原代码是 memcpy 且能证明调用点都不重叠 → 保持 memcpy（换 memmove 虽然安全，
  但改变了可观察的性能特征，且"证明全部调用点"的成本高）；
- 原代码就有重叠场景（比如自处理缓冲区）→ 它本来就是 UB，你的任务是不让
  改写扩大 UB 的影响面，不是修它（修复 = 行为变更）。

**反例**：
```c
/* 坏：提取辅助函数时把 memmove 换成 memcpy（"更快"）——
   原作者选 memmove 是因为调用点有重叠 */
```

## 2. 字符串截断与终止符：一字节之差就是 stdout 之差

**模式**：`strncpy(dst, src, n)`（截断时不写 NUL）、`snprintf(dst, n, ...)`
（总是写 NUL）、手动 `dst[n-1] = '\0'`、拼接时缓冲区刚好装满。

**危险（通道）**：终止符位置/有无决定后续 `strlen`/`printf` 输出多少字节 →
**stdout / stderr / 文件内容漂移**，甚至越界读 → **signals（SIGSEGV）**。

**行为保持的改写**：
- 照抄原函数的终止符契约：strncpy 的"可能不终止"就是行为，不要换成
  snprintf（两者截断后的字节内容不同——strncpy 填零到 n，snprintf 截断即停）；
- 边界算式 `n - 1`、`n + 1` 保持原样；提取辅助函数时把 `sizeof` 与 `strlen`
  的选择一起带走（`sizeof buf` 含 NUL，`strlen(s)` 不含）。

**反例**：
```c
/* 坏：strncpy(dst, src, n); dst[n-1] = '\0'; 被"简化"成 snprintf(dst, n, "%s", src);
   两者在 len < n 时尾部字节不同（strncpy 填零、snprintf 不动）——
   若下游 dump 整个缓冲区，文件内容漂移 */
```

## 3. 严格别名：换个类型指针读内存是 UB

**模式**：`*(int *)&floatvar`、用 `char*` 以外的类型指针 reinterpret 缓冲区、
`union` 之外的双关。

**危险（通道）**：优化器按别名假设重排读写 → 读到"想象中"的值 →
**stdout / exit code 漂移**。

**行为保持的改写**：
- 保持原有的访问类型路径不变；原代码用 `memcpy` 做类型双关 → 继续 memcpy；
- 不把"通过 char* 逐字节访问"重写成"直接按目标类型访问"（char* 是别名规则
  唯一的例外，换来的是别的通道代价）。

## 4. in-place（d == s）是真实调用场景，不是巧合

**模式**：原地把字符串转小写、就地去除字符、`f(s, s)` 这类调用。

**危险（通道）**：改写引入临时缓冲区会改变中间状态可见性；改写遍历顺序会
改变 in-place 的结果 → **stdout / 文件内容漂移**。

**行为保持的改写**：
- 保持读写指针的推进顺序（先读后写、写后自增的次序是行为）；
- 不把原地算法改写成"先拷贝再处理"——即使结果字节相同，失败路径上的
  部分写入状态不同（**filesystem / 内存副作用时序**）；
- 测试侧有 `d==s` 用例是常态（empty / exact-fit / 原地），别让它们变成 REJECTED。

## 5. restrict：承诺是行为的一部分

**模式**：`void f(int *restrict a, int *restrict b)`——调用方保证不重叠。

**危险（通道）**：删掉 restrict 或改写内部假设会同时改变优化行为与契约 →
性能特征变化（可观察的时序）或 UB 暴露面变化。

**行为保持的改写**：
- 签名不动（红线 5），函数体也不得以"我知道不会重叠"为由删减守卫；
- 提取辅助函数时把 restrict 语义一起带走，不要在辅助函数里丢掉。

## 6. 数组与指针的退化陷阱

**模式**：`sizeof(arr)` 在参数里变成 `sizeof(ptr)`、`char arr[10]` 作参数
后 `sizeof` 给 8、`&arr` 与 `arr` 的类型差异。

**危险（通道）**：提取函数时把数组参数化，`sizeof` 突变 → 拷贝/清零的字节数
变了 → **stdout / 文件内容 / 越界崩溃（signals）**。

**行为保持的改写**：
- 数组到指针的退化点必须显式：长度要么作为参数一起传，要么 `static_assert`/
  注释钉死容量；
- 不把栈上定长数组"顺手"改成指针+malloc——分配失败路径是新行为
  （**exit code / signals**），且 `sizeof` 语义全变。
