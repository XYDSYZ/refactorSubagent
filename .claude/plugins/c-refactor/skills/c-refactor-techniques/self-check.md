# 自检清单

结束前逐条过。任何一条答不上来，回到代码证明它，或放弃那部分改写。

## 逐通道自问（对每一段被改写的代码）

| 通道 | 自问 | 抓法回顾 |
|---|---|---|
| exit code | 我的改写会改变任何 return/exit 的值吗？任何分支的走向吗？ | 错误码语义、短路求值、边界比较 |
| signals | 会引入崩溃/UB 吗？会改变 abort/raise 的发生吗？ | 溢出、越界、别名、双重关闭 |
| stdout | 会改变输出的字节、行数、顺序、时机吗？ | 部分输出、缓冲、格式串、常量 |
| stderr | 错误路径的输出（perror/strerror/格式）逐字节相同吗？ | errno 保存顺序、输出调用替换 |
| filesystem | 会改变写文件的字节、路径、创建/删除的顺序吗？ | 失败点前的部分写入、flush 时机 |

## 红线复查（改了什么就查哪条）

- [ ] 有符号运算的中间量：类型、宽度、有无符号，与改写前逐一相同？
- [ ] 每个有副作用的调用：求值次数与顺序不变？
- [ ] 每个宏：展开后的 token 序列不变（参数括号、do-while(0)、#if 分支）？
- [ ] 每个 static/全局：所有权没动、初始化时机没动、覆写时序没动？
- [ ] 每条错误路径：清理调用个数/顺序/返回值检查一致？
- [ ] 每个字符串操作：终止符契约（strncpy vs snprintf vs 手写）一致？
- [ ] 函数签名、链接性、头文件声明：零改动？
- [ ] 没有引入新的算法、缓存、并发、IO 折叠？

## 编译验证（Bash，结束前必做）

系统提示词里写了构建输出的位置。典型循环：

```
restructure → compile → fix → recompile → stop
```

- 编译警告新增了？通常意味着隐式转换/未使用值变了——查 integer-and-overflow.md。
- 编译失败 = 交付作废，宿主验证一定 ABORTED，先修到干净再结束。

## 证明不了的部分：如实上报

总结里写清：
1. 改了什么、为什么等价（引用上面的通道）；
2. **哪一段没有证明、为什么停下**——这是合法且有价值的交付，
   远好过一个被验证 REJECTED 的"完整"重构。

> 验证系统不接受讨价还价：任何一条通道的漂移 = REJECTED，
> 没有例外、没有辩解空间。宁少勿漂。
