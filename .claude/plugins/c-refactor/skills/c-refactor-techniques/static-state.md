# 静态状态与重入

每条格式：**模式 → 危险（通道）→ 行为保持的改写 → 反例**。
"通道"指验证系统对比的 observable channel：exit code / signals / stdout / stderr / filesystem。

## 1. 函数内 static：初始化时机与跨调用记忆都是行为

**模式**：`static int count = 0; count++;`、`static char buf[N];`、
`static table[] = {...}` 的惰性/一次性初始化。

**危险（通道）**：把 static 改成局部变量 = 丢掉跨调用记忆 → 第二次调用
结果漂移 → **stdout / exit code 漂移**；把 static 提升为全局 = 链接可见性
变化 + 其他 TU 可能同名冲突（编译/链接失败）。

**行为保持的改写**：
- static 变量原位保留；提取辅助函数时**不移动** static 的所有权
  （谁记忆它，它就留在谁的函数里）；
- 初始化表达式里的非零值/函数调用（C99 起 static 局部只能常量初始化——
  原代码若用运行时赋值 + 首调标志模拟惰性初始化，该结构原样保留）；
- 不合并两个"看起来相同"的 static 缓冲区：它们可能被调用方并发/交错使用，
  合并 = 状态互踩 → **stdout 漂移**（测试用交错调用用例抓）。

**反例**：
```c
/* 坏：strtok 风格的自制解析器，static 指针记忆上次位置——
   提取"辅助函数"时把指针变成参数，调用方每次传 NULL
   → 续解析行为丢失，第二段解析结果为空 → stdout 漂移 */
```

## 2. 非可重入函数：调用序列即契约

**模式**：`strtok`（内部状态）、`localtime`/`gmtime`（共享静态结果区）、
`readdir`（目录流位置）、返回内部缓冲区的函数（`strerror`、`getenv` 的
environ 依赖）。

**危险（通道）**：改写调用序列（多调一次/少调一次/交错调用两个流）→
内部游标状态不同 → **stdout / 文件遍历顺序漂移**。

**行为保持的改写**：
- 调用次数与顺序逐条保持；`strtok(NULL, ...)` 的 NULL 语义链不被提取打断；
- 两个目录流的交错 readdir 顺序保持（哪怕看起来"乱"）；
- 不把 `localtime` 换成 `localtime_r`（线程安全版本）——返回值指向的内存
  语义不同，且这是行为变更。

## 3. 返回内部指针的函数：生命周期横跨调用

**模式**：`return cache;` / `static char msg[64]; sprintf(msg,...); return msg;`。

**危险（通道）**：调用方持有的指针在下一次调用后失效——改写改变了
"何时覆写"的时序 → 调用方读到不同内容 → **stdout 漂移**。

**行为保持的改写**：
- 缓冲区的覆写时机保持：只在每次调用都覆写、还是命中缓存跳过覆写，
  是调用方可见的差异；
- 缓冲区大小/布局不动（越界写位置变了就是 UB 面变了）；
- 不把"返回内部指针"改成"拷贝到调用方缓冲"——那是 API 变更（红线 5）。

## 4. 全局状态：读写点与初始化顺序

**模式**：全局配置变量、全局计数器、`g_init` 守卫、跨 TU 的 extern 全局。

**危险（通道）**：全局变量的初始化顺序（跨 TU 未指定）、读写点增减 →
初始化竞争结果不同 → **stdout / exit code 漂移**。

**行为保持的改写**：
- 全局变量的定义 TU、extern 声明、初始化器原样保留；
- 函数内对全局的**读写次数**保持（读两次 vs 读一次缓存到局部，在无并发时
  值相同——但有信号处理器/回调写入时可见；证明没有才可缓存）；
- 守卫检查（`if (!g_init) init();`）原样保留在原位置。

## 5. 可重入性改造是行为变更，不是重构

**模式**：把非可重入函数改成"可重入版本"（static → 参数传入上下文）。

**危险（通道）**：这是 API 变更（签名变了），且调用方代码全部要改 →
违反红线 5。哪怕所有调用点都同步改了，可观察行为在单线程下"等价"，
但函数成为库的一部分时外部调用方不可见地被破坏。

**行为保持的改写**：
- 不做。任务要求"提取辅助函数/重组内部结构"，重入改造不在其列；
- 若任务文本明确要求重入化，那它是行为变更任务——照常实现，但总结里
  明确写"这是契约变更"，不冒充行为保持。

## 6. 静态常量表：只读共享是安全的边界

**模式**：`static const int table[] = {...};`、查表替代计算。

**危险（通道）**：把 `static const` 提成宏/内联字面量会膨胀代码段；
把"查表"改成"计算"或反之是**算法替换**（红线 4）——浮点/边界值差异 →
**stdout 漂移**。

**行为保持的改写**：
- 表数据与查表代码一起移动/提取，索引边界检查原样；
- 表内容一字不改；`static const` 限定符保持（它决定放 data 段还是 rodata 段，
  误写行为的抓法不同——保持声明即保持防线）。
