# 编写期间不运行：一次真实测试（2026-10-28）

本轮按用户明确的职责调整：test-writer 与 build-writer 只交付代码和说明，宿主随后编译、运行并记录结果。一次真实模型编写后，宿主首次构建成功，等价修改被接受，两个固定错误修改被行为断言拦截。两个编写角色的 shell 调用均为零。

## 实现变化

- 删除 build-writer 提交前在临时目录试编译、运行成功的要求；test-writer 同样不再执行编译、语法探测或模拟工作流。
- 保留编写时的源码调查、依赖选择、辅助 C 代码、构建/测试工作流与使用说明。需要运行时才能确定的条件写入工作流，由宿主检查；交付不以提前运行成功为条件。
- Bash 暂时从两个角色各自的工具列表移除。test-writer 使用 `TEST_WRITER_AGENT_TOOLS`，build-writer 使用 `BUILD_WRITER_AGENT_TOOLS`，恢复时只需调整对应列表。通用 driver 的 shell 支持仍保留，没有新增模式开关。
- 同步共用调查提示词、宿主事实说明和相关 skill，避免其他指导继续要求提前实测。
- 生成工作流中的真实编译、执行、状态检查、产物断言和双侧比较机制保持原有流程。

当前真实 C 编译失败的自动回传修复尚未实现：宿主会记录诊断并中止；现有自动修复针对工作流源码策略违规。本轮未扩展该反馈路径，也未通过预先编译弥补它。

## 复核发现的限制

1. **生成的 BuildWorkflow 有跨平台路径判断错误。** 它把空的 `executable_suffix` 当作无法确定路径并抛错，但空后缀在 Linux/macOS 是合法值。TestWorkflow 正确读取该字段；构建工作流的检查仍会阻断那些平台。本次 Windows 构建不受影响，不能据此声称这份生成方案跨平台可用。没有运行 Linux/macOS。
2. **有一项输入前提需要确认。** 辅助程序向只有 16 字节的目标缓冲区传入 `SIZE_MAX` 容量，借短源验证长度计算。当前实现没有越界，但该输入超出通常的缓冲容量约定；在未确认契约前，不应把它当作已证明合理的边界覆盖，也有过度约束后续实现的风险。
3. 仍绑定固定的 `src/text_copy.c`，没有覆盖合法拆分文件后的构建适应性；也没有验证真实库消费者、外部依赖故障注入或真实重构模型。
4. 本轮所有构建成功，没有实测编译失败后的反馈修复。固定错误只证明这两个行为错误可被本轮生成测试识别，不证明覆盖完备。

这些发现保留在复核记录中，本次没有修改已经固定的生成材料，也没有为了让汇总通过而追加测试。当前改动验证的是“编写交付、宿主执行”的职责边界，以及该 Windows 场景能否运行。
