# Redis 与依赖模拟的全流程用例

## 用例结构与边界

本批新增七个标准 `cases/<id>/case.json`，均由现有执行器发现，`subject=e2e`、
`tag=project-evaluation`。每例的正常路径是：准备干净源码 → AI 调查并编写构建/测试代码 →
AI 重构 → 宿主用同一套辅助材料分别构建运行原版与修改版 → 比较 → 独立可信复核。
编写阶段的工具权限与生产流程保持现状；模型不需要自己编译运行。

任务简报只描述重构目标与行为保持要求，不预告应选测试方式、参考向量或错误补丁。
源码环境不含参考判据。新增判据与评分参考位于环境目录之外，独立复核使用的材料只在模型阶段结束后注入。
这是测试工具的材料分离，延续现有约定，不等同于新增操作系统沙箱。

Redis 固定为官方 8.10.3 / `1a2574ce1551d3de6e0b4a56756c0fdbc6659e4f`。
本批 Redis 用例声明 Linux；Windows 上应在 WSL 中运行整条链。独立设备工程为仓库内可重建的合成项目，
声明 Windows/Linux，未声称它属于 Redis 或某个真实设备 SDK。

## 会话预算

2026-10-30 起，七例都将 `sessions.testWriter.deadlineMs` 和 `sessions.refactor.deadlineMs`
显式设为 `null`，取消原来的 20 分钟会话总预算，覆盖用户或项目层的同名配置。
测试编写默认轮数不限；无消息检测、单次构建 360 秒、测试 210 秒、命令 180 秒及执行器单例总超时 90 分钟独立生效。
历史运行仍按当时生效的配置解释，取消预算不改变已有中止裁决，也不代表取消后已经重跑成功。

## 七个场景

| 用例 | 重构目标 | 可信检查的重点 | 难度 |
|---|---|---|---|
| `e2e-redis-r1-sds` | `sdssplitargs` 的引号状态与重复判断 | 15 项；空 token、引号、转义 NUL/FF、错误后 argc 与释放 | 低至中 |
| `e2e-redis-r2-set` | SET 选项识别与互斥判断 | 13 项自编检查 + 上游字符串测试；NX/XX/GET/KEEPTTL、错误原子性 | 中 |
| `e2e-redis-r3-listpack` | `lpInsert` 的准备与头部更新 | 14 项操作序列；编码边界、增长/收缩、正反遍历、整数与完整性 | 中至高 |
| `e2e-redis-r4-dict` | `dictFindLinkForInsert` 的桶内查重 | 9 项；碰撞、迁移中两张表、重复键、扫描完整性与释放 | 高 |
| `e2e-redis-r5-resp` | 请求解析的长度与有效性判断 | 9 项自编检查 + 上游协议测试；实际分片、流水线、非法帧后连接健康 | 高 |
| `e2e-redis-r6-aof` | `aofInfoFormat` 文件名与偏移字段 | 12 项；文本转义、偏移、真实关闭重启、多份增量顺序、损坏清单 | 高 |
| `e2e-mock-transport` | `frame_fetch` 的三段重复收发循环 | 17 项；真实业务实现 + 外部通信替身、部分 I/O、重试、总时限、校验、输出与释放 | 高 |

这里的项数指可信辅助程序/工作流的稳定语义检查，不是模型生成测试的数量。上游通过数取决于该次真实运行，
不能用历史 179/27 代替当次证据。测试方式允许与参考不同，是否合适由覆盖、真实执行与评分综合判断。

R1/R3/R4 的参考路径为局部编译，保留真实分配器、时钟等依赖；R2 组合已有测试与新增命令检查；
R5/R6 使用真实服务器和新客户端。R4 的可控哈希与析构回调只用于稳定碰撞及记录资源所有权，
SCAN 允许重复，不固定顺序。R5 用另一连接查询待测连接的缓冲状态，确认未完成输入已到达服务端后才补齐，
不会把两次 send 或固定 sleep 当作触发分片的证明。

## 需要模型自行实现的通信依赖

设备工程的公开头文件与 README 提供完整 ABI、请求/响应格式、错误码、时限和所有权约定。
生产 CMake 要求 DeviceSDK 4，但工程不附 SDK 二进制、硬件或测试实现。
有效方案需要替换通信边界并编译当前侧 `src/frame_client.c`，不能复制业务算法或直接模拟 `frame_fetch`。

可信替身检查：单字节分段收发与暂时不可用；空/最大/二进制响应；错误标识与校验和；
长度超过协议上限、容量不足、头部或数据中途断开、永久失败；连接失败；零时限、连续重试耗尽时限、
多次操作共享总时限。失败必须保持输出和输出长度，成功打开的连接在每条路径释放一次。
时钟从非零值开始，避免测试和实现错误依赖零纪元。

其有效重构对照把收发循环提取到新的 `src/frame_io.c` / 内部头文件，同时更新 CMake。
这也检查参考构建是否支持合法新增 C 文件。固定错误分别破坏分段写入偏移、响应校验和、失败连接回收。

## 独立可信复核

`case.json` 新增可选 `verification`，只属于测试执行器，不下发给 Agent：

```json
{
  "verification": {
    "resource": "workflows/redis-r1-sds-reference",
    "inject": [{"source": "resources/judge/redis-8.10.3/r1-sds", "dest": "refactor-task/reference"}],
    "changedFiles": ["src/sds.c"]
  }
}
```

实际配置还注入共享支持头文件。主流程接受候选后，执行器读取保存的 base/commit 证据，通过 Git 提取候选补丁，
在新的一对 worktree 里使用固定构建/测试重放；不复用模型生成的辅助程序、二进制或数据库目录。
必须至少修改一个目标文件、两侧构建与测试有效、声明非空且比较一致。缺失或失败的复核不能让用例通过。
主流程拒绝或中止时记录 `not-run`，保留原裁决。

参考材料摘要钉在测试工作流里，执行前后核对；复用的上游 Tcl 判据和设备公开契约也检查原始摘要。
服务器以前台进程、每侧独立目录和相对 Unix socket 运行，正常关闭并在异常时回收。
局部参考构建会识别 `src/` 下新增 C 文件，支持合法函数拆分；服务构建仍使用该侧维护后的 Makefile。

`run-result.json` 与重判均保存 `independentVerification`。它与主流程 `state` 分开报告，
因此主流程 ACCEPTED、独立复核失败时，整体评测仍失败。仅改注释或改名的任务完成度继续由补丁复核/评分判断，
目标文件发生变化本身不证明实质性重构。
裁判输入同时包含独立复核状态、保存的候选补丁，以及构建登记的辅助源码材料，便于审查真实实现与依赖替身。

## 如何运行

```sh
# 列出/检查七个用例，不调用模型
bun testset/run.ts --list --tag project-evaluation
bun testset/run.ts --dry-run --tag project-evaluation

# 零模型成本：七类参考判据的有效重构/错误对照校准，使用新的输出目录
bun scripts/calibrate-project-cases.ts --out runs/project-controls-new

# Windows 可以单独校准通信场景
bun scripts/calibrate-project-cases.ts --only e2e-mock-transport --out runs/mock-controls-new

# 真正的 AI 编写 + AI 重构 + 独立复核；会调用已配置模型
bun testset/run.ts --only e2e-redis-r1-sds --out runs/redis-ai-new
bun testset/run.ts --only e2e-mock-transport --out runs/mock-ai-new

# 需要评分时，提供现有的裁判命令；未评分的任务质量不能视为已通过
bun testset/run.ts --only e2e-mock-transport --out runs/mock-ai-scored-new --rubric-cmd "claude -p" --rubric-min 0.8
```

Redis 需要 Git、GCC、Make、Bash。R2/R5 的准备阶段另检查 versioned Tcl 8.5+，缺失则 blocked；
其余参考路径不强制 Tcl。建议将输出目录设在 Linux 原生文件系统，以减少源码/构建文件访问开销。
首次源码获取可使用 pin 中的 remote，不要求存在本轮调查目录。通信场景只需要 Git、GCC 与 Bun。
上游字符串/协议单元通过 TCP 连接；参考调用使用 Redis 自带 `--config unixsocket '""'` 关闭其未使用的
Unix socket，避免嵌套评测目录使绝对 socket 路径超过 Linux 限制。自编客户端仍使用每侧独立目录内的相对 socket。
上游脚本的退出码 1 既可能来自断言失败，也可能来自它自己的全局超时；参考工作流因此额外拒绝
`[TIMEOUT]`，并要求出现当前单元的完整执行结束记录。只有正常完成的行为断言失败才能作为检出证据。

校准脚本通过公开 CLI 调用产品，不导入生产执行模块。共 22 个固定对照：7 个有效重构、15 个错误修改。
每个错误都要求指定语义检查失败，且两侧编译成功、基线检查有效、候选测试正常完成；编译失败、崩溃、
超时、零测试或环境错误不能冒充错误检出。基线无效时停止该场景剩余对照。
正对照还走一遍独立复核入口。输出不能覆盖已有目录，详细证据保留在各控制的 session 下。

## 证据等级

代码和用例配置已实现；固定对照校准证明参考判据与执行链路，不能证明模型已经写出同等质量的测试或完成重构。
真实模型结果、模型身份、任务质量得分与漏测情况必须由单独保存的 AI 运行证据报告。

独立复核另有真实负向实验：主测试运行辅助程序但只比较退出码，故意漏掉错误校验和，主流程得到 ACCEPTED；
隐藏判据重建同一候选后以 `checksum-output-atomicity` 拒绝它，整体评测为 failed。
证据位于 `runs/mv-c/run-result.json` 和 `runs/redis-cases-dev/verify-replay-c.log`。这证明“主流程接受”不会绕过复核。

## 本轮真实 AI 通信场景

Windows 上运行 `bun testset/run.ts --only e2e-mock-transport --out runs/ml-a`，
实际模型记录为 `deepseek-v4.1-flash`，工作流编写与重构阶段均为 AI，没有注入固定重构补丁。

- 模型选择局部 C 程序，并自行实现 `transport_*` 替身、可控时钟和 28 个场景。
  构建登记了一份约 25 KB 的辅助 C 源码，直接编译每侧真实 `src/*.c`，不要求缺失的 DeviceSDK。
- 两侧构建通过，测试各产生 57 项比较声明且一致；测试报告为每侧 28 个场景，失败 0。
  替身覆盖部分读写、临时不可用、二进制/空/最大响应、错误校验和、错误类型、容量、连接失败、时限与失败回收。
- 候选只修改 `src/frame_client.c`，把三段重复收发循环提取为 `transfer_exact`；
  同一个交换起始时刻贯穿读写，输出仍在校验成功后发布，连接沿原有出口释放。属于实质性内部职责拆分。
- 独立复核重新构建该候选，17 项固定检查全部通过，状态 ACCEPTED，失配为空。

主流程耗时 1507.430 秒（约 25 分 7 秒）；编写约 17 分 32 秒，重构 396.656 秒，正式双侧验证 45.085 秒。
包含准备、独立复核和报告阶段的原始整次记录约 26 分 14 秒。编写会话没有 Bash 调用；
重构会话有自己的额外编译/对比操作，不应把它们算作宿主正式判据或编写阶段执行。

人工复核发现一个实际质量缺口：生成测试将部分确切读写次数、读取字节数和剩余预算序列一同断言/比较，
这些细节可能误拒绝其他合理实现。它验证了本次候选，不能因此宣称测试设计已经完善或覆盖所有合法重构。
质量评分尚未调用外部裁判，状态为 `pending-rubric`，没有虚构模型分数。

报告阶段暴露评分器原有两个兼容问题：把参考 Markdown 当目录读取、只在 session 目录寻找已保存源码。
本轮已修正，增加辅助材料与独立补丁证据；利用已保存的结果重新生成评分输入，没有重跑模型或修改固定测试。
原始错误汇总 `runs/ml-a/summary.json` 保留，恢复后的检查在 `runs/ml-a/summary.reviewed.json`，
完整评分输入在 `runs/ml-a/e2e-mock-transport/rubric-prompt.md`。

上述 2026-10-28 批次只对通信场景调用真实模型。2026-10-29 已另行调用全部七例，
结果为 3 例通过、4 例中止；逐阶段耗时、实际补丁、额外诊断与模型评分见
[`12-project-ai-results-2026-10-29.md`](12-project-ai-results-2026-10-29.md)，不与本节历史运行混算。
