# RESP 分片与错误恢复

目标：`src/networking.c`。任务与协议保持要求见任务简报。

参考检查见 `resources/judge/`；固定对照如下。

- equivalent：提取数组长度验证，保留转换失败的短路行为，期望 ACCEPTED。
- bulk-length-garbage：错误忽略 bulk 长度中的尾部垃圾，期望 REJECTED。
- reject-empty-bulk：错误拒绝合法的空参数，期望 REJECTED。

复核生成方案是否调用当前侧真实实现，是否保持外部接口与资源所有权，是否有效执行而非只声明成功。测试方式无需与参考相同。实质性的辅助函数提取和任务完成度需要结合候选补丁人工或模型评分，单纯改名不能作为任务完成。

## 行为与质量复核要点

目标是当前侧真实服务器的请求长度解析；参考组合 9 项自编协议检查与上游 protocol Tcl 单元。
有效分片需要证明未完成输入已到达服务端（参考经另一连接查询 qbuf），不能只靠两次发送或固定 sleep。
覆盖跨段 CRLF、含 NUL 的 bulk、多个流水线命令与空参数、负数/尾部垃圾/数组溢出；非法连接关闭后其他连接应仍健康。
错误对照只放宽数字后的尾部字符，保留非数字/溢出拒绝，使上游整组能够正常结束。超时、崩溃、零测试不能冒充检出。
